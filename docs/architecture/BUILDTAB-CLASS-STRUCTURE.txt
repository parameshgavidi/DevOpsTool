================================================================================
BuildTab.razor — move inline @code into structured class files
Paste-ready architecture guide for the .NET MAUI Blazor Hybrid DevOps Tool
================================================================================

WHY
---
BuildTab.razor @code has grown into a "god file": git, build, publish copy,
DB rollup, email, day-wise logs, MSI setup, migration folders, process runners.

Goal:
  - BuildTab.razor     → markup + thin UI event handlers only
  - BuildTab.razor.cs  → UI state fields + injects services + calls them
  - Services/*.cs      → real work (one responsibility per class)


================================================================================
ALREADY IN YOUR APP (GssDevOpsAutomationTool) — DO NOT DUPLICATE
================================================================================
  Services/IBuildService.cs + Services/BuildService.cs already provide:
    RunCommandAsync(...)
    ResolveMsBuildPath(bool netFramework)
    ResolveVisualStudioIdePath()

  That pair IS the process runner. Do NOT add a second ProcessRunner class.
  See: docs/architecture/EXISTING-BUILDSERVICE-ALIGN.txt

WHAT BuildTab.razor.cs LOOKS LIKE AFTER (thin)
================================================================================

    public partial class BuildTab : ComponentBase
    {
        // --- injects (see STEP 9) ---

        // --- UI state only ---
        private string LogOutput = "";
        private List<Application> BuildApps = new();
        private string RepoRoot = "";
        private string FromBranch = "";
        private string ToBranch = "";
        private List<string> DbBranchOptions = new();
        private bool _isBuilding;
        private bool _isGettingLatest;
        private bool _showApps;
        private CancellationTokenSource? _buildCts;

        private async Task GetLatestClicked()
        {
            _isGettingLatest = true;
            await InvokeAsync(StateHasChanged);
            try
            {
                await Git.GetLatestRepoRootAsync(RepoRoot, AppendToUiLog);
                await LoadApplicationsFromConfigAsync();
                _showApps = true;
            }
            finally
            {
                _isGettingLatest = false;
                await InvokeAsync(StateHasChanged);
            }
        }

        private async Task BuildAllAsync()
        {
            if (_isBuilding || BuildApps.Count == 0) return;
            _isBuilding = true;
            await InvokeAsync(StateHasChanged);
            try
            {
                foreach (var app in BuildApps)
                    await Build.BuildApplicationAsync(app, /* context */, AppendToUiLog, _buildCts!.Token);
            }
            finally
            {
                _isBuilding = false;
                await InvokeAsync(StateHasChanged);
            }
        }

        private async Task BundleClicked()
        {
            await DbRollup.BundleAsync(/* settings from UI */, AppendToUiLog);
            await Notify.SendDbScriptsEmailAsync(/* … */, AppendToUiLog);
        }

        private void AppendToUiLog(string text)
        {
            LogOutput += text;
            Logs.Append(RepoRoot, text);
        }
    }

================================================================================
RULES WHILE REFACTORING
================================================================================

1. Services must NOT call StateHasChanged or touch Blazor UI controls.
   Pass Action<string> log / return data; BuildTab updates UI.

2. Do NOT put IConfiguration reads inside every method — load BuildSettings
   once (OnInitialized) and pass values / a settings object into services.

3. Keep Application / BuildSettings in Models/DeploymentModels.cs (already).

4. One class = one job. If a method needs git + process + paths, inject those
   services — do not copy-paste Process.Start again.

5. Prefer moving the EXACT working method body first (cut/paste), then clean
   naming. Do not rewrite and move in the same step.

6. After extraction, delete the old private method from BuildTab so there is
   only ONE implementation (same lesson as LoadDbBranchesAsync duplicates).
