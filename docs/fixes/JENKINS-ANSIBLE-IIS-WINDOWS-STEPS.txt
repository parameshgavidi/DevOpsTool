WHAT WE ALREADY DID (JENKINS DID EVERYTHING)
--------------------------------------------
Job GSSWebIIS (local Windows Jenkins) ran these stages in ONE job:

  1. Get latest GSSWeb          git fetch / restore
  2. Build GSSWebComponent      MSBuild, copy DLL into site Bin
  3. Backup IIS                 copy C:\inetpub\wwwroot\GSSWeb
  4. Deploy to IIS              stop app pool, Copy-Item, start pool
  5. Smoke test                 GET http://localhost/

Paste file we used:
  docs/fixes/GSSWebIIS-Jenkins-script-3.txt
  docs/fixes/JENKINS-GSSWEB-IIS-PIPELINE.txt

Laptop install we used:
  docs/fixes/JENKINS-WINDOWS-IIS-PIPELINE-STEPS.txt


WHAT WE DO NOW (TWO JOBS)
-------------------------
  Job A  gssweb-ci       Jenkins. Git, build, tests, zip, Artifactory.
  Job B  gssweb-deploy   Jenkins starts Ansible. Ansible does 3–5 above
                         PLUS Windows Server / IIS configuration.

  Developer commit Git
          |
          v
  Jenkins CI  (windows agent)
    Checkout → MSBuild GSSWebComponent → tests → zip gssweb-iis.zip
    SonarQube + Security Gate (existing EBS jobs)
    Upload zip + deploy-manifest to Artifactory
    Create Release Bundle
          |
          v
  Deploy Request JSON
          |
          +-- DEV / SIT --> run deploy pipeline now
          |
          +-- CAT / PRD --> Change Request first, then deploy pipeline
          |
          v
  Ansible (control node → WinRM → Windows Server)
    Connection test (ucd_{EIR}_ebs)
    Configure IIS features, app pool, site
    Download zip from Artifactory
    Backup IIS
    Stop app pool, copy files, start app pool
    Smoke test
          |
          v
  Application running on Windows IIS

PART 1 — PREREQUISITES (FY26 GUIDE)
================================================================================
Do these before you change any Jenkins job. The FY26 guide lists
them as required.

1. Existing CI/CD pipeline
   Your team should already have EBS pipeline jobs for:
     building
     SonarQube scanning
     Artifactory upload
     Security Gate
   This notepad walks you through adding the Ansible deploy steps.
   Do not throw away the EBS build / scan / upload jobs.

2. Ansible service account
   BPL or BSA requests a Windows Domain Service Account — USA
   in eAccess. Naming convention:

     ucd_{EIR}_ebs
     example:  ucd_9999_ebs

   Only users with manager access can request the account.
   See the FY26 page  Configure Ansible for Automated Deployments
   for the full eAccess request (parameters + security groups).

3. Verify Ansible connectivity
   Test the connection to the Ansible non-production tower so NIT
   has granted the required permissions.
   Use the EBS sample job:  Ansible Connection Test
   A green ping means WinRM + ucd_{EIR}_ebs can reach the Windows
   hosts. Do not start a deploy until this is green.

4. Request Ansible templates
   Email  NITInfrastructureDesign@usgs.gov  and ask for Ansible
   templates for ALL environments and EACH deployable component.

   Environments:  DEV, SIT, CAT, PRD
   Your component type for GSSWeb:  IIS / Windows  (Copy Files)

   The FY26 examples list Tomcat, WebSphere, Oracle, batch.
   GSSWeb is none of those. Say that clearly in the request:

     Application: GSSWeb (classic ASP.NET Web Forms / IIS)
     Deploy type: Copy Files into IIS (not MSI, not Tomcat)
     Site / pool / path: GSSWeb / GSSWeb / C:\inetpub\wwwroot\GSSWeb
     We already ran this with Jenkins PowerShell on a VDI.
     Please provide the IIS / Windows Ansible template, or confirm
     we may use ansible/deploy-iis.yml from our repo until then.

   Also attend the DevSecOps Daily Working Session (10:30 EST)
   for breakout rooms per component type.

Checklist before PART 2:

PART 2 — DEVELOPER COMMITS CODE IN GIT
================================================================================
This replaces "Get latest" on the VDI (git fetch of F:\GSS\AppDev\gss-root).

1. Developer works on GIT_BRANCH (example: main, or a release branch).
2. Commit the .NET change. Push to origin.

     git add ...
     git commit -m "..."
     git push origin GIT_BRANCH

3. EBS Jenkins job gssweb-ci is triggered:
     - webhook from Git, or
     - Pipeline script from SCM polling, or
     - Build Now

Jenkins clones GIT_URL. It does not depend on F:\GSS\AppDev\gss-root
being already on the controller.

Private repo: Jenkins credentials ID (same question as
AWS-JENKINS-TEAM-QUESTIONS.txt item 5).

PART 3 — JENKINS BUILDS .NET, RUNS TESTS, CREATES ARTIFACTS
================================================================================
Job name:  gssweb-ci
File:      jenkins/Jenkinsfile.dotnet-ci
Agent:     label windows  (MSBuild lives here, same as before)

This Jenkinsfile is a template in DevOpsTool. The CI job must see
the GSS source (WebV3\gssweb, Shared Components\GSSWebComponent):

  A. Paste jenkins/Jenkinsfile.dotnet-ci into the EBS job
     (same as we pasted GSSWebIIS-Jenkins-script-3.txt), OR
  B. Copy that file into the GSS Git repo and use
     Pipeline script from SCM (Script Path below).

Do not point SCM at DevOpsTool and expect GSSWeb to compile.

Create the job:

1. EBS Jenkins → New Item → Name: gssweb-ci → Pipeline → OK
2. Pipeline → Definition: Pipeline script from SCM
     SCM: Git
     Repository URL: GIT_URL   (the GSS app repo, not DevOpsTool)
     Credentials: (item 5)
     Branch: */GIT_BRANCH
     Script Path: jenkins/Jenkinsfile.dotnet-ci
3. Save. Do not deploy from this job.

Stages in jenkins/Jenkinsfile.dotnet-ci (same MSBuild as GSSWebIIS):

  Checkout Git
    git status, git rev-parse
    (Declarative Pipeline already checked out the repo)

  Build GSSWebComponent
    Find MSBuild (VS 18, VS 2022, then MSBUILD_EXE)
    Skip Crystal Reports Backup Files csproj
    msbuild GSSWebComponent.csproj /p:Configuration=Release /t:Build
    Copy GSSWebComponent.dll into WebV3\gssweb\gssweb\Bin
    Do NOT FolderProfile the .sln (SSRS MSB4226)
    Do NOT aspnet_compiler (CS1647)

  Run tests
    If any *Tests.dll exists under bin\Release or bin\Debug,
    run vstest.console.exe. If none, skip (GSSWeb website often
    has no unit-test assembly). A failing test fails the job.
    Do not upload a zip from a red test stage.

  Package artifact
    Copy website folder (skip .git, packages, .sln, .resx)
    Zip to artifacts\gssweb-iis.zip
    Write / copy deploy-manifest.json next to the zip

  Upload to Artifactory
    Only if ARTIFACTORY_URL is set.
    Prefer the existing EBS Artifactory / JFrog plugin step
    (FY26: you should already have this job). The Jenkinsfile
    has a PLACEHOLDER echo until that URL is filled in.

  post
    archiveArtifacts artifacts\gssweb-iis.zip  (Jenkins copy)
    The deployable unit is that zip, not the Jenkins workspace.

Green CI means: zip exists, DLL is in Bin, tests did not fail.
It does NOT mean IIS was updated. Ansible does that.

Paste-only option (no SCM file yet):
  Open jenkins/Jenkinsfile.dotnet-ci, paste the whole file into
  the job's Pipeline script box, swap PLACEHOLDERS, Save,
  Build Now. After it is green, switch to Pipeline script from SCM.

PART 7 — ANSIBLE CONFIGURES WINDOWS SERVER AND DEPLOYS TO IIS
================================================================================
Job name:  gssweb-deploy
File:      jenkins/Jenkinsfile.ansible-deploy
Agent:     label ansible  (Linux control node, NOT the old laptop)

Official EBS path
  The existing Deployment Pipeline Execution job consumes the
  deploy request and runs NIT templates. Use that job when NIT
  has given you the IIS / Windows template. Parameters:

    ENVIRONMENT        DEV or SIT (CAT/PRD after CR)
    ARTIFACT_VERSION   CI build number
    deploy request     JSON from PART 5

Lab path (until the template exists)
  1. New Item → gssweb-deploy → Pipeline
  2. Pipeline script from SCM
       Script Path: jenkins/Jenkinsfile.ansible-deploy
  3. Build with parameters:
       ENVIRONMENT = DEV
       ARTIFACT_VERSION = (the green gssweb-ci number)
  4. CAT/PRD parameter values fail the Guard CAT/PRD stage on
     purpose until the CR is approved.

What ansible/deploy-iis.yml does on each Windows host
(same order as the old Jenkins PowerShell):

  A. Server configuration (new — used to be a one-time manual step)
     Enable IIS + ASP.NET 4.8 features
     Create app pool GSSWeb, managedRuntimeVersion v4.0
     Create site GSSWeb on IIS_HTTP_PORT
     Physical path C:\inetpub\wwwroot\GSSWeb

  B. Get the zip
     Download from Artifactory, or copy artifacts/gssweb-iis.zip
     Unzip to C:\temp\gssweb-deploy\site

  C. Backup IIS
     Copy current site to C:\inetpub\backups\GSSWeb\yyyyMMdd-HHmmss
     Same idea as Jenkins stage Backup IIS.

  D. Deploy
     Stop-WebAppPool GSSWeb  (wait up to 30s)
     Copy files, skip .git, packages, .sln, .resx
     Start-WebAppPool GSSWeb
     Fail if the pool is not Started

  E. Smoke test
     GET http://localhost:IIS_HTTP_PORT/
     Fail on HTTP >= 400
     Console: Application is running on IIS site GSSWeb

Run by hand from the control node (lab):

  ansible-galaxy collection install ansible.windows community.windows

  ansible-playbook -i ansible/inventories/dev.ini ansible/deploy-iis.yml \
    --extra-vars "artifact_version=42 artifactory_url=https://..."

    http://DEV-WEB-01/          (or the host header NIT assigned)

  Wait until connections = 0
  Deploy one server
  Return to LB (health.dat → health.gif)

  does not, keep the drain / return as a pre / post step.

PART 9 — DEV / SIT vs CAT / PRD
================================================================================
DEV / SIT  (FY26: Running your pipeline for DEV/SIT)

  1. Developer push

  3. SonarQube + Security Gate green
  4. Artifactory + Release Bundle
  5. deploy-request-dev.json or deploy-request-sit.json
  6. Run gssweb-deploy / EBS deploy pipeline

  5. Fill docs/samples/deploy-request-cat.json
  6. Generate the Change Request with that payload
  7. Wait for approval
  8. Run the deploy pipeline
  9. Confirm the site

jenkins/Jenkinsfile.ansible-deploy refuses CAT/PRD without that
approval step (Guard CAT/PRD stage).

================================================================================

PART 12 — TROUBLESHOOTING
================================================================================
gssweb-ci — MSBuild not found
  Same as GSSWebIIS. Search VS 18, VS 2022, then MSBUILD_EXE.
  docs/fixes/gssweb-msbuild-not-recognized.txt

gssweb-ci — Crystal Reports Backup Files csproj
  Recurse + First 1 picked the backup project (CS2001).
  Skip any path under "Crystal Reports Backup Files".
  Real project:
    Shared Components\GSSWebComponent\GSSWebComponent.csproj

gssweb-ci — MSB4226 SSRSReports.rptproj
  Do not FolderProfile gssweb.sln. CI only builds the component
  DLL and zips the website folder.

gssweb-ci — tests skipped
  Normal when there is no *Tests.dll. If you add a test project,
  the stage starts running vstest automatically.

Artifactory upload skipped
  ARTIFACTORY_URL is empty. Jenkins still archives the zip.
  Fill the URL or use the existing EBS upload job.

Ansible Connection Test red
  WinRM closed, wrong user, or NIT has not granted the account
  on that host. Fix ping before deploy. Do not skip this.

Ansible cannot stop / start app pool
  Import-Module WebAdministration must run as a local admin
  equivalent. ucd_{EIR}_ebs needs that right on the IIS box.
  If the pool is Stopping forever: iisreset, then re-run.

Zip missing on the Windows server
  CI never uploaded, or artifact_version does not match the
  Artifactory folder. Open the Release Bundle and copy the
  exact path into the extra-vars.

Smoke test HTTP 500
  Files arrived, app crashed. Check Web.config and
  Windows Event Viewer → Application.
  App pool must be v4.0 (not "No Managed Code").
  This is classic ASP.NET, not ASP.NET Core — no Hosting Bundle.

Smoke test hits the wrong site
  Jenkins is still 8080. IIS is 80 (or the NIT host header).
  Do not point IIS_HTTP_PORT at the Jenkins port.

CAT/PRD job failed immediately
  Guard CAT/PRD is supposed to fail until the CR is approved.
  Use DEV/SIT, or remove that stage only after the CR process
  is wired to Jenkins.
