ROOT CAUSE — setupSolutionPath is a .csproj
--------------------------------------------------------------------------------
Your appsettings (from the screenshot):

  "projectPath":
    "Windows Services\\GSS Dispatch Service\\GSSDispatchService\\GSSDispatchService.csproj"

  "setupProjectPath":
    "Windows Services\\GSS Dispatch Service\\GSSDispatchServiceSetup\\GSSDispatchSetup.vdproj"

  "setupSolutionPath":
    "Windows Services\\GSS Dispatch Service\\GSSDispatchService.csproj"   ← WRONG

setupSolutionPath must be the .sln that CONTAINS GSSDispatchSetup.
You copied projectPath (the service .csproj) into setupSolutionPath.

devenv /build /project /projectconfig only works with a solution:

  devenv "something.sln" /build "Release|Any CPU" /project "GSSDispatchSetup" /projectconfig "Release"

When the first argument is a .csproj, devenv tries to open the project
(and look for a same-name .sln next to it). /build + /project are not
valid in that mode → HELP dump → exit != 0 → no MSI.

    so the installer Primary Output has an .exe to wrap)
