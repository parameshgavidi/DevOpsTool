================================================================================
BuildTab / GSS.GSSEmail — FileNotFoundException: System.Data.SqlClient
MAUI Blazor Hybrid (GssDevOpsAutomationTool) on .NET 10 / Windows
================================================================================

SYMPTOM
-------
- Bundle / build completes
- UI LogOutput shows: [INFO] Email notification sent to ...
- No email arrives
- No error in Build tab LogOutput ("not getting any error")


ERROR (Visual Studio → View → Output → Debug)
---------------------------------------------
GenerateSystemLogFileEntry: An error occurred while Sending Emails
System.IO.FileNotFoundException: Could not load file or assembly
  'System.Data.SqlClient, Version=0.0.0.0, Culture=neutral,
   PublicKeyToken=b03f5f7f11d50a3a'. The system cannot find the file specified.

Where it throws (inside GSSEmailComponent, swallowed before BuildTab):
  GSS.GSSEmail.SendEmailByNetV2
    → EmailCredentialList(...)     ← needs SQL to read SECUREMAILCREDENTIAL
    → System.Data.SqlClient        ← MISSING on .NET / MAUI
  Source: GSSEmail.cs (EmailCredentialList ~line 314)

Why BuildTab shows success with no error:
  SendEmailByNetV2 catches Exception, calls GenerateSystemLogFileEntry
  (Debug.WriteLine + DB), and does NOT rethrow.
  BuildTab then logs "[INFO] Email notification sent..." after the call returns.


CAUSE
-----
GSSEmailComponent was built for .NET Framework-style hosting where
System.Data.SqlClient ships with the runtime.

GssDevOpsAutomationTool is .NET 10 MAUI. SqlClient is NOT in the shared
framework — it must be an explicit NuGet (or DLL) dependency of the STARTUP
project so it appears in GssDevOpsAutomationTool.deps.json.

Same class of bug as Encryption.dll FileNotFound on MAUI:
  file-on-disk / Framework assumption ≠ deps.json registration.


--------------------------------------------------------------------------------
FIX (preferred) — add System.Data.SqlClient NuGet to the MAUI startup project
--------------------------------------------------------------------------------

1. Open the STARTUP project (GssDevOpsAutomationTool.csproj), NOT only
   GSSEmailComponent.

2. Package Manager Console (Default project = GssDevOpsAutomationTool):

     Install-Package System.Data.SqlClient

   Or CLI from the MAUI project folder:

     dotnet add package System.Data.SqlClient

   Or edit the .csproj:

  <ItemGroup>
    <PackageReference Include="System.Data.SqlClient" Version="4.9.0" />
  </ItemGroup>

   (Use the latest stable 4.x if 4.9.0 is not available in your feed.)

3. Why NOT Microsoft.Data.SqlClient alone?
   GSSEmailComponent.dll was compiled against the assembly name
   System.Data.SqlClient. Microsoft.Data.SqlClient is a different assembly
   name — it will NOT satisfy this FileNotFoundException unless you rebuild
   GSSEmail to use Microsoft.Data.SqlClient.

4. Rebuild the STARTUP project (Clean → Rebuild).

5. VERIFY deps.json (proof the package registered):

  Open:
    bin\Debug\net10.0-windows10.0.19041.0\win-x64\GssDevOpsAutomationTool.deps.json
  Search for:  "System.Data.SqlClient"
  You MUST see entries under "targets" / "libraries".

6. VERIFY output folder has the DLL, e.g.:
    bin\Debug\net10.0-windows10.0.19041.0\win-x64\System.Data.SqlClient.dll
  (and platform natives NuGet may copy under runtimes\...)


--------------------------------------------------------------------------------
FIX B — explicit Reference (only if you cannot use NuGet)
--------------------------------------------------------------------------------
If your feed blocks the package, copy System.Data.SqlClient.dll next to your
other GSS libs and Reference it the same way as Encryption.dll:

  <ItemGroup>
    <Reference Include="System.Data.SqlClient">
      <HintPath>libs\System.Data.SqlClient.dll</HintPath>
      <Private>true</Private>
    </Reference>
  </ItemGroup>

Prefer FIX A (NuGet) so transitive natives / deps.json stay correct.


--------------------------------------------------------------------------------
AFTER SqlClient LOADS — next failures to watch
--------------------------------------------------------------------------------
Once SqlClient is fixed, the NEXT common failure is:

  ArgumentException: Keyword not supported: 'huixt2azeur...'
  + Missing SECUREMAILCREDENTIAL data in Process Settings

That means BuildTab passed an ENCRYPTED connection string into
EmailCredentialList. Fix decrypt-before-send here:

  docs/fixes/gssemail-encrypted-connectionstring.txt

Other later failures (after plaintext CS works):

  1) Truly missing SECUREMAILCREDENTIAL row in Process Settings
  2) Bad decrypted Host / Port / UserId / Pwd
  3) SMTP / TLS failure on smtpClient.Send

Those still only appear in Output → Debug (GenerateSystemLogFileEntry),
not in BuildTab LogOutput, until you surface errors (optional below).


--------------------------------------------------------------------------------
OPTIONAL — surface YOUR failures in BuildTab LogOutput (no GSSEmail edit)
--------------------------------------------------------------------------------
You cannot make SendEmailByNetV2 rethrow. You CAN still catch decrypt mistakes
in BuildTab (FIX A guard). For failures inside GSSEmail, watch Output → Debug.

Do NOT add typeof(System.Data.SqlClient.SqlConnection) probes that require
editing GSSEmail — keep PackageReference on the MAUI csproj only.


--------------------------------------------------------------------------------

--------------------------------------------------------------------------------

HOW TO READ THE DIAGNOSTIC
--------------------------
1. exists=False AND deps=False
   → package not added / wrong project / wrong TFM. Apply FIX A.

2. exists=True AND deps=False
   → Copy alone is not enough on .NET 10. Need PackageReference or Reference
     so deps.json lists it.

3. exists=True AND deps=True AND still FileNotFound Version=0.0.0.0
   → Wrong RID / natives missing, or another dependent assembly missing.
     Check Output for the next FileNotFound after SqlClient is fixed.


--------------------------------------------------------------------------------
DO NOT
--------------------------------------------------------------------------------
- Expect "email sent" in LogOutput to mean SMTP succeeded
- Add only Microsoft.Data.SqlClient when GSSEmail still binds System.Data.SqlClient
- Fix only GSSEmailComponent.csproj if the MAUI app loads a prebuilt DLL
  (the STARTUP app must own the PackageReference)
- Rely on .NET Framework GAC / machine-wide SqlClient on MAUI
