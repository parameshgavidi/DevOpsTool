================================================================================
Build All → InvalidOperationException: thread not associated with Dispatcher
Fix HandleBuildSuccessChanged in PARENT tabs (NOT BuildTab)
================================================================================

SYMPTOM
-------
Click Build All (or Build). Debugger stops on StateHasChanged():

  System.InvalidOperationException:
  The current thread is not associated with the Dispatcher.
  Use InvokeAsync() to switch execution to the Dispatcher when triggering
  rendering or component state.

Typical crash site (signature may use "success" or "hasSuccessfulBuild"):

  private Task HandleBuildSuccessChanged(bool hasSuccessfulBuild)
  {
      HasSuccessfulBuild = HasSuccessfulBuild || hasSuccessfulBuild;
      StateHasChanged();              // ← throws
      return Task.CompletedTask;
  }


WHERE THE METHOD ACTUALLY LIVES
-------------------------------
HandleBuildSuccessChanged is NOT in BuildTab.razor.

Find-in-solution for "HandleBuildSuccessChanged" shows hits like:

  DeployTab.razor
    ~line 74:  <BuildTab OnBuildSuccessChanged="HandleBuildSuccessChanged" />
    ~line 150: private Task HandleBuildSuccessChanged(bool success)

  DeploymentTool.razor
    ~line 38:  <DeployTab ... OnBuildSuccessChanged="HandleBuildSuccessChanged" />
    ~line 180: private Task HandleBuildSuccessChanged(bool hasSuccessfulBuild)

BuildTab only RAISES the event (EventCallback), for example:

  [Parameter] public EventCallback<bool> OnBuildSuccessChanged { get; set; }

  // after a successful build:
  await OnBuildSuccessChanged.InvokeAsync(true);

Parents HANDLE that event. Fix the handlers in DeployTab + DeploymentTool.


ROOT CAUSE
----------
Build / Build All finishes work on background (thread-pool) threads.
BuildTab then calls OnBuildSuccessChanged.InvokeAsync(true).
That runs the parent HandleBuildSuccessChanged off the UI thread.

In .NET MAUI Blazor Hybrid, StateHasChanged() MUST run on the Blazor
dispatcher. Calling it from a background thread throws the exception above.


--------------------------------------------------------------------------------
1) DeployTab.razor — FIX HandleBuildSuccessChanged
--------------------------------------------------------------------------------
Find (near line 150):

    private Task HandleBuildSuccessChanged(bool success)
    {
        // ... may set a flag / forward to parent ...
        StateHasChanged();
        return Task.CompletedTask;
    }

REPLACE StateHasChanged() + CompletedTask with InvokeAsync.

Option A:

    private Task HandleBuildSuccessChanged(bool success)
    {
        // keep your existing flag / forward logic, e.g.:
        // HasSuccessfulBuild = HasSuccessfulBuild || success;
        // await OnBuildSuccessChanged.InvokeAsync(success);  // if you forward
        return InvokeAsync(StateHasChanged);
    }

Option B (async) — use this if the method also awaits a parent callback:

    private async Task HandleBuildSuccessChanged(bool success)
    {
        // keep existing logic that sets flags / forwards:
        // HasSuccessfulBuild = HasSuccessfulBuild || success;
        if (OnBuildSuccessChanged.HasDelegate)
            await OnBuildSuccessChanged.InvokeAsync(success);

        await InvokeAsync(StateHasChanged);
    }

Adjust parameter name (success vs hasSuccessfulBuild) to match YOUR file.
Keep whatever flag / forward logic you already have — only change how you re-render.


--------------------------------------------------------------------------------
2) DeploymentTool.razor — FIX HandleBuildSuccessChanged
--------------------------------------------------------------------------------
Find (near line 180) — this often matches the debugger crash exactly:

    private Task HandleBuildSuccessChanged(bool hasSuccessfulBuild)
    {
        HasSuccessfulBuild = HasSuccessfulBuild || hasSuccessfulBuild;
        StateHasChanged();              // ← throws
        return Task.CompletedTask;
    }

REPLACE with:

    private Task HandleBuildSuccessChanged(bool hasSuccessfulBuild)
    {
        HasSuccessfulBuild = HasSuccessfulBuild || hasSuccessfulBuild;
        return InvokeAsync(StateHasChanged);
    }

Or:

    private async Task HandleBuildSuccessChanged(bool hasSuccessfulBuild)
    {
        HasSuccessfulBuild = HasSuccessfulBuild || hasSuccessfulBuild;
        await InvokeAsync(StateHasChanged);
    }

Do NOT keep:

    StateHasChanged();
    return Task.CompletedTask;
