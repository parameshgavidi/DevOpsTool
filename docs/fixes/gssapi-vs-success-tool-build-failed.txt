================================================================================
GSS API — VS Build succeeds, DevOpsTool Build fails
================================================================================

SYMPTOM
-------
- Visual Studio (e.g. VS 2026): Build GSSApi.sln → SUCCESS
  (e.g. "Build: 23 succeeded, 0 failed" — often Debug)
- DevOpsTool Build tab for "GSS API" → FAILED


WHY (VS vs command tool are NOT the same command)
-------------------------------------------------
Visual Studio "Build":
  - Builds projects it can load (skips incompatible ones like SSRS .rptproj)
  - Usually Debug
  - Does NOT run "dotnet publish"
  - Does NOT run appsettings gitLatestCommand

DevOpsTool Build (your appsettings):
  - Runs:  dotnet publish "{projectFile}" -c Release -o {outputSubfolder}
  - {projectFile} = projectPath → currently GSSApi.sln
  - Publish on a .sln fails when the solution contains:
      * SSRSReports.rptproj (incompatible / not SDK)
      * other non-publishable / non-SDK projects
      * multiple apps fighting over the same -o folder
  - Also uses Release (VS often showed Debug\net9.0)

Your CURRENT gitLatestCommand (from screenshot) is ALSO risky:

  git fetch && git clean -fd -- "Web Services\GSSApi" && git restore ...

  git clean -fd DELETES untracked files under GSSApi before build.
  That can remove local files the API needs and is unrelated to VS Build.


================================================================================
FIX — paste into appsettings.json for "GSS API"
================================================================================

USE THIS BLOCK (publish the API .csproj only — not the whole .sln):

{
  "name": "GSS API",
  "type": "DotNetCoreApi",
  "projectPath": "Web Services\\GSSApi\\GSSApi\\GSSApi.csproj",
  "gitLatestCommand": "git stash push -m \"devops-pre-build\" -- \"Web Services\\GSSApi\" && git fetch && git restore --source=@{u} --staged --worktree -- \"Web Services\\GSSApi\" && (git stash pop || ver > nul)",
  "buildCommand": "dotnet publish \"{projectFile}\" -c Release -o {outputSubfolder}",
  "outputSubfolder": "GSSApi"
}

================================================================================
If Build still fails after appsettings fix
================================================================================

Check DevOpsTool OUTPUT LOG for:

  A) "dotnet is not recognized"
     → Install .NET 9 SDK; reopen tool; ensure PATH has dotnet

  B) error MSB3202 / project file does not exist
     → projectPath casing/folder wrong — folder is GSSApi (not GSSAPI)
     → confirm file exists:
       dir "Web Services\GSSApi\GSSApi\GSSApi.csproj"

  C) NU1101 / restore failed
     → run once:  dotnet restore "Web Services\GSSApi\GSSApi\GSSApi.csproj"

  D) Get latest failed / No stash entries found
     → must end with (git stash pop || ver > nul)
     → see also: docs/fixes/gss-api-build-publish.txt

  E) @{u} / no upstream
     → set upstream on current branch, or Get latest restore fails

Unload SSRSReports in Visual Studio is fine for IDE comfort.
It does NOT affect Get latest or Build in the command tool
(those use git + dotnet on paths from appsettings).
