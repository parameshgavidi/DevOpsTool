WHY IT FAILS TODAY
------------------
1. projectPath points to a .sln file:
     "Web Services\\GSSWebService\\GSSWebService.sln"
   DeployOnBuild + PublishProfile work on a .csproj, not reliably on a .sln.

2. buildCommand uses PublishProfile=FolderProfile but does NOT set the publish
   destination to your OutputRoot / build-output folder. If FolderProfile is
   missing or points elsewhere, publish fails or artifacts go to the wrong place.

3. buildCommand replaces {projectFile} but never uses {outputSubfolder}.
   BuildTab.razor already replaces {outputSubfolder} with the FULL output folder
   from GetAppOutputFolder() = {OutputRoot}\GSSWebService
   (or .\build-output\GSSWebService when OutputRoot is empty).

4. Comparing to "Test GSS Service": that entry uses a .csproj path. GSS Web
   Service should do the same.

FIX 1 — Corrected appsettings.json entry (replace GSS Web Service block)
--------------------------------------------------------------------------------
Copy this into your build.apps array (adjust .csproj path if your project file
name differs):

{
  "name": "GSS Web Service",
  "type": "AsmxWebService",
  "projectPath": "Web Services\\GSSWebService\\GSSWebService.csproj",
  "buildCommand": "msbuild \"{projectFile}\" /t:Rebuild /p:Configuration=Release /p:DeployOnBuild=true /p:WebPublishMethod=FileSystem /p:PublishProvider=FileSystem /p:PublishUrl=\"{outputSubfolder}\\\" /p:DeleteExistingFiles=True /p:SelfContained=false",
  "outputSubfolder": "GSSWebService"
}

What this does:
- Builds the .csproj (not the .sln)
- Publishes via FileSystem (no FolderProfile required)
- Writes artifacts to {OutputRoot}\GSSWebService
  which is typically:  <OutputRoot or .\build-output>\GSSWebService

--------------------------------------------------------------------------------
FIX 3 — Ensure GetProjectFilePath prefers .csproj over .sln
--------------------------------------------------------------------------------
If GetProjectFilePath() currently returns whatever is in ProjectPath (including
.sln), add a small guard so .sln is resolved to a .csproj when possible.

ADD / UPDATE helper (BuildTab.razor @code):

    private string? GetProjectFilePath(Application app)
    {
        if (string.IsNullOrWhiteSpace(app.ProjectPath))
            return null;

        var fullPath = Path.IsPathRooted(app.ProjectPath)
            ? app.ProjectPath
            : Path.Combine(RepoRoot, app.ProjectPath);

        // Prefer .csproj — DeployOnBuild / publish need a project, not a solution
        if (fullPath.EndsWith(".sln", StringComparison.OrdinalIgnoreCase))
        {
            var dir = Path.GetDirectoryName(fullPath);
            if (!string.IsNullOrEmpty(dir) && Directory.Exists(dir))
            {
                var csproj = Directory.GetFiles(dir, "*.csproj").FirstOrDefault();
                if (csproj is not null)
                {
                    LogOutput += $"[{DateTime.Now:HH:mm:ss}] [INFO] Resolved .sln to project: {csproj}\r\n";
                    return csproj;
                }
            }
        }

        return fullPath;
    }
