GSSWeb — NuGet Install-Package vs gitLatestCommand (local changes wiped)
================================================================================

QUESTION
--------
Install-Package Microsoft.AspNet.WebApi.Client -Version 4.0.20710
adds local changes. Our gitLatestCommand removes local changes before build.
Will the package install survive?


ANSWER (updated — keep local, no push to remote)
------------------------------------------------
YES — change gitLatestCommand in appsettings.

Team will NOT push package fixes to remote. Keep local Install-Package changes,
still get latest from repo, then build.

REPLACE the wipe command:

  OLD: git fetch && git clean -fd -- "..." && git restore --source=@{u} ...

  NEW: git stash push -m "devops-pre-build" -- "WebV3\\gssweb"
       && git fetch
       && git restore --source=@{u} --staged --worktree -- "WebV3\\gssweb"
       && git stash pop

That stashes local edits → takes latest for that folder → re-applies local.


DO NOT put the package in appsettings.json
------------------------------------------
appsettings holds the gitLatestCommand string — not NuGet package names.
"Microsoft.AspNet.WebApi.Client" does not belong there as a package entry.


RECOMMENDATION
--------------
1. Change gitLatestCommand to stash → fetch → restore → stash pop (see
   docs/fixes/git-latest-before-build.txt).
2. Keep local Install-Package on the build machine (no remote push required).
3. Do NOT use git clean -fd in gitLatestCommand if you need local changes.
