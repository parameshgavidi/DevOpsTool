CAUSE
-----
1) The DevOps tool starts cmd.exe WITHOUT the Visual Studio developer PATH.
   Bare "msbuild" is not found. (When buildCommand started with msbuild,
   the tool injected the full MSBuild.exe path — that is why older builds
   could run MSBuild at all.)

2) Working directory is the SOLUTION folder, not repo root:
     F:\GSS\AppDev\gss-root\WebV3\gssweb
   So "Shared Components\..." and "WebV3\gssweb\gssweb\Bin\..." are WRONG
   from this cwd. Use absolute F:\GSS\AppDev\gss-root\... paths.

Keep the ver>nul & PREFIX so the tool does not rewrite the chain
into one MSBuild.exe process (MSB1008 / Switch: &&).
