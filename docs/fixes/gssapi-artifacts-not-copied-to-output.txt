GSS API — Why artifacts are NOT in F:\build-output\GSSApi
================================================================================

YOUR SETUP (from screenshot)
----------------------------
appsettings:

  "type": "DotNetCoreApi"
  "projectPath": "Web Services\\GSSApi\\GSSApi\\GSSApi.csproj"
  "buildCommand": "msbuild \"{projectFile}\" /p:Configuration=Release /p:OutputPath={outputSubfolder}"
  "outputSubfolder": "GSSApi"

Output Root explorer (F:\build-output) shows:
  db-scripts
  GSSWebService          ← copied (AsmxWebService / PrecompiledWeb flow)
  Web2ClientBridge       ← copied (MVC / setup flow)
  Web2ClientBridge_...
  (NO GSSApi folder)


================================================================================
WHY — two separate reasons
================================================================================

REASON 1 — Your buildCommand never writes to F:\build-output
------------------------------------------------------------
  /p:OutputPath={outputSubfolder}
  → {outputSubfolder} becomes just "GSSApi"
  → MSBuild writes compile output to a RELATIVE "GSSApi" folder
    (under the project / working dir — NOT under Output Root)

  OutputPath ≠ Publish.
  It only redirects bin output. It does NOT create F:\build-output\GSSApi.


REASON 2 — DevOpsTool does NOT copy DotNetCoreApi to Output Root
----------------------------------------------------------------
After exit == 0, BuildTab only looks for PrecompiledWeb for:

  - AsmxWebService  (GSS Web Service)  → copy PrecompiledWeb → outputFolder
  - AspNetWebForms  (GSSWeb)           → copy PrecompiledWeb → outputFolder

DotNetCoreApi / "GSS API" has NO else-if branch.
So even when build "succeeds", you get:

  [WARN] Publish output not found for GSS API under {workingDir}

and F:\build-output\GSSApi is never created/filled.

That is why GSSWebService appears in F:\build-output but GSSApi does not.


================================================================================
FIX — publish STRAIGHT into Output Root (no copy needed)
================================================================================

Do NOT use OutputPath={outputSubfolder}.
Use PublishDir / -o with {outputFolder} (full path = OutputRoot\GSSApi).


OPTION A — MSBuild Publish (recommended if VS Build works)

{
  "name": "GSS API",
  "type": "DotNetCoreApi",
  "projectPath": "Web Services\\GSSApi\\GSSApi\\GSSApi.csproj",
  "gitLatestCommand": "git stash push -m \"devops-pre-build\" -- \"Web Services\\GSSApi\" && git fetch && git restore --source=@{u} --staged --worktree -- \"Web Services\\GSSApi\" && (git stash pop || ver > nul)",
  "buildCommand": "msbuild \"{projectFile}\" /t:Restore;Publish /p:Configuration=Release /p:PublishDir=\"{outputFolder}\\\\\" /v:m",
  "outputSubfolder": "GSSApi"
}


OPTION B — dotnet publish

{
  "name": "GSS API",
  "type": "DotNetCoreApi",
  "projectPath": "Web Services\\GSSApi\\GSSApi\\GSSApi.csproj",
  "gitLatestCommand": "git stash push -m \"devops-pre-build\" -- \"Web Services\\GSSApi\" && git fetch && git restore --source=@{u} --staged --worktree -- \"Web Services\\GSSApi\" && (git stash pop || ver > nul)",
  "buildCommand": "dotnet publish \"{projectFile}\" -c Release -o \"{outputFolder}\"",
  "outputSubfolder": "GSSApi"
}


If OUTPUT LOG still shows literal {outputFolder}, hardcode:

  "buildCommand": "dotnet publish \"{projectFile}\" -c Release -o \"F:\\build-output\\GSSApi\""

  or MSBuild:

  "buildCommand": "msbuild \"{projectFile}\" /t:Restore;Publish /p:Configuration=Release /p:PublishDir=\"F:\\\\build-output\\\\GSSApi\\\\\" /v:m"


--------------------------------------------------------------------------------
OLD (wrong) vs NEW
--------------------------------------------------------------------------------
OLD:  /p:OutputPath={outputSubfolder}     → relative "GSSApi", no Output Root
NEW:  /p:PublishDir="{outputFolder}\\"    → F:\build-output\GSSApi
  or  -o "{outputFolder}"


================================================================================
OPTIONAL — BuildTab.razor code fix (if you want tool to COPY like GSSWeb)
================================================================================
Only needed if buildCommand writes somewhere else and you want archive+copy.

Inside if (exit == 0), ADD else if for DotNetCoreApi BEFORE the
"if (!string.IsNullOrEmpty(precompiled))" block:

            else if (string.Equals(app.Type, "DotNetCoreApi", StringComparison.OrdinalIgnoreCase)
                     || string.Equals(app.Name, "GSS API", StringComparison.OrdinalIgnoreCase))
            {
                // Prefer publishing directly to outputFolder via buildCommand.
                // If command used a local folder, point precompiled at that folder:
                //   e.g. Path.Combine(workingDir, app.OutputSubfolder ?? "GSSApi")
                // Better: leave this unused and publish with -o "{outputFolder}".
                precompiled = null;
            }

Preferred approach remains: publish with "{outputFolder}" so no copy code is required.
