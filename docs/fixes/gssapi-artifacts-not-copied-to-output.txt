GSS API — literal folder "{outputFolder}" created under Web Services\GSSApi
================================================================================

WHAT YOU SAW
------------
Explorer path:

  F:\GSS\AppDev\gss-root\Web Services\GSSApi\{outputFolder}

A folder whose NAME is exactly:  {outputFolder}

That means the placeholder was NOT replaced. MSBuild/dotnet used the
literal string "{outputFolder}" as the publish/output path.


================================================================================
WHY
================================================================================
In BuildTab buildCommand substitution, these ARE typically replaced:

  {projectFile}        → full path to GSSApi.csproj
  {outputSubfolder}    → "GSSApi"  (name only — NOT Output Root)

{outputFolder} (full path F:\build-output\GSSApi) is often replaced ONLY in
setup/MSI commands — NOT in the main buildCommand.

So this command:

  msbuild ... /p:PublishDir="{outputFolder}\\"
  or
  dotnet publish ... -o "{outputFolder}"

creates:

  F:\GSS\AppDev\gss-root\Web Services\GSSApi\{outputFolder}\


Also: DotNetCoreApi has NO PrecompiledWeb copy into F:\build-output.
So even a good build will not create F:\build-output\GSSApi unless the
publish command itself writes there.


================================================================================
FIX NOW — hardcode Output Root in appsettings (USE THIS)
================================================================================
Delete the bad folder when convenient:

  rmdir /s /q "F:\GSS\AppDev\gss-root\Web Services\GSSApi\{outputFolder}"


Paste this GSS API block (Output Root = F:\build-output):


{
  "name": "GSS API",
  "type": "DotNetCoreApi",
  "projectPath": "Web Services\\GSSApi\\GSSApi\\GSSApi.csproj",
  "gitLatestCommand": "git stash push -m \"devops-pre-build\" -- \"Web Services\\GSSApi\" && git fetch && git restore --source=@{u} --staged --worktree -- \"Web Services\\GSSApi\" && (git stash pop || ver > nul)",
  "buildCommand": "msbuild \"{projectFile}\" /t:Restore;Publish /p:Configuration=Release /p:PublishDir=\"F:\\\\build-output\\\\GSSApi\\\\\" /v:m",
  "outputSubfolder": "GSSApi"
}


OR with dotnet:

{
  "name": "GSS API",
  "type": "DotNetCoreApi",
  "projectPath": "Web Services\\GSSApi\\GSSApi\\GSSApi.csproj",
  "gitLatestCommand": "git stash push -m \"devops-pre-build\" -- \"Web Services\\GSSApi\" && git fetch && git restore --source=@{u} --staged --worktree -- \"Web Services\\GSSApi\" && (git stash pop || ver > nul)",
  "buildCommand": "dotnet publish \"{projectFile}\" -c Release -o \"F:\\build-output\\GSSApi\"",
  "outputSubfolder": "GSSApi"
}


buildCommand only (MSBuild — preferred if VS Build works):

  msbuild "{projectFile}" /t:Restore;Publish /p:Configuration=Release /p:PublishDir="F:\build-output\GSSApi\\" /v:m

buildCommand only (dotnet):

  dotnet publish "{projectFile}" -c Release -o "F:\build-output\GSSApi"


After Build, you should see:

  F:\build-output\GSSApi\   ← real publish files
  NOT under Web Services\GSSApi\{outputFolder}


--------------------------------------------------------------------------------
DO NOT use
--------------------------------------------------------------------------------
- -o "{outputFolder}"              → creates literal {outputFolder} folder
- /p:PublishDir="{outputFolder}\\" → same problem
- /p:OutputPath={outputSubfolder}  → relative "GSSApi", not F:\build-output


================================================================================
OPTIONAL CODE FIX — make {outputFolder} work in buildCommand
================================================================================
In BuildApplication, where buildCommand placeholders are replaced, ADD:

    command = command
        .Replace("{projectFile}", projectFile, StringComparison.OrdinalIgnoreCase)
        .Replace("{outputSubfolder}", app.OutputSubfolder ?? string.Empty, StringComparison.OrdinalIgnoreCase)
        .Replace("{outputFolder}", outputFolder, StringComparison.OrdinalIgnoreCase);

(outputFolder should already be Path.Combine(OutputRoot, app.OutputSubfolder).)

After that code fix you MAY use "{outputFolder}" in appsettings again.
Until then — hardcode F:\build-output\GSSApi.
