--------------------------------------------------------------------------------
WHAT THIS MEANS
--------------------------------------------------------------------------------
- NOT the old cmd HELP (/useenv) problem anymore — Process/devenv works.
- Classic .vdproj command-line bug: Visual Studio Installer Projects refuse
  out-of-process / command-line validation unless EnableOutOfProcBuild = 0.
- Web project built OK; only Web2ClientBridge.Setup failed validation.


--------------------------------------------------------------------------------
STEP 1 — Close Visual Studio (required)
--------------------------------------------------------------------------------
Close ALL Visual Studio / devenv windows before fixing registry or rebuilding.
Command-line Setup build often fails if the IDE has the .sln open.


--------------------------------------------------------------------------------
STEP 2 — Run DisableOutOfProcBuild.exe (PREFERRED)
--------------------------------------------------------------------------------
Installer Projects ships a helper. For YOUR machine (VS 18 Professional):

  F:\Program Files\Microsoft Visual Studio\18\Professional\Common7\IDE\CommonExtensions\Microsoft\VSI\DisableOutOfProcBuild\DisableOutOfProcBuild.exe

If that path is missing, search:

  dir /s /b "F:\Program Files\Microsoft Visual Studio\18\DisableOutOfProcBuild.exe"

IMPORTANT: run it FROM its own folder (cwd must be that folder):

  cd /d "F:\Program Files\Microsoft Visual Studio\18\Professional\Common7\IDE\CommonExtensions\Microsoft\VSI\DisableOutOfProcBuild"
  DisableOutOfProcBuild.exe

Run as the SAME Windows user that runs the DevOps tool.

This sets EnableOutOfProcBuild = 0 for that VS instance.


--------------------------------------------------------------------------------
STEP 3 — Or set registry manually (if exe missing)
--------------------------------------------------------------------------------
Open regedit as the DevOps tool user. Create DWORD = 0 named EnableOutOfProcBuild
under MSBuild for your VS 18 hive. Typical paths (pick the ones that exist):

  HKEY_CURRENT_USER\Software\Microsoft\VisualStudio\18.0\MSBuild
  HKEY_CURRENT_USER\Software\Microsoft\VisualStudio\18.0_Config\MSBuild

VS may use an instance suffix, e.g.:

  HKEY_CURRENT_USER\Software\Microsoft\VisualStudio\18.0_<InstanceId>_Config\MSBuild

How to find the right key:
  1. Regedit → HKEY_CURRENT_USER\Software\Microsoft\VisualStudio\
  2. Find folders starting with 18.0
  3. Under each, create MSBuild if missing
  4. New DWORD: EnableOutOfProcBuild = 0

PowerShell (run as same user; adjusts common hives):

  $names = @('18.0','18.0_Config') +
    (Get-ChildItem HKCU:\Software\Microsoft\VisualStudio -ErrorAction SilentlyContinue |
     Where-Object { $_.PSChildName -like '18.0*_Config' -or $_.PSChildName -eq '18.0' } |
     ForEach-Object PSChildName)
  $names = $names | Select-Object -Unique
  foreach ($n in $names) {
    $p = "HKCU:\Software\Microsoft\VisualStudio\$n\MSBuild"
    New-Item -Path $p -Force | Out-Null
    New-ItemProperty -Path $p -Name EnableOutOfProcBuild -PropertyType DWord -Value 0 -Force | Out-Null
    Write-Host "Set $p\EnableOutOfProcBuild = 0"
  }


--------------------------------------------------------------------------------

--------------------------------------------------------------------------------
Close VS. Open cmd:

  "F:\Program Files\Microsoft Visual Studio\18\Professional\Common7\IDE\devenv.com" ^

If IDE Build works but command line still 8000000A → STEP 2/3 not applied

--------------------------------------------------------------------------------
STEP 5 — Optional: call DisableOutOfProcBuild from BuildTab before devenv
--------------------------------------------------------------------------------
In BuildSetupProjectAsync, BEFORE RunProcessCaptureAsync(devenv...), add:

        // Allow .vdproj command-line / devenv builds (HRESULT 8000000A)
        var vsRoot = Path.GetFullPath(Path.Combine(Path.GetDirectoryName(devenvPath)!, "..", "..", ".."));
        // devenv is ...\Common7\IDE\devenv.com → vsRoot = VS install root
        var disableDir = Path.Combine(
            Path.GetDirectoryName(devenvPath)!,
            "CommonExtensions", "Microsoft", "VSI", "DisableOutOfProcBuild");
        var disableExe = Path.Combine(disableDir, "DisableOutOfProcBuild.exe");
        if (File.Exists(disableExe))
        {
            LogOutput += $"[{DateTime.Now:HH:mm:ss}] [INFO] Running DisableOutOfProcBuild.exe...\r\n";
            var disableExit = await RunProcessCaptureAsync(
                disableExe,
                "",
                disableDir,
                line =>
                {
                    lock (_pendingLogBuffer)
                    {
                        _pendingLogBuffer.Append(line);
                        if (!line.EndsWith('\n') && !line.EndsWith('\r'))
                            _pendingLogBuffer.AppendLine();
                    }
                },
                cancellation);
            LogOutput += $"[{DateTime.Now:HH:mm:ss}] [INFO] DisableOutOfProcBuild exit {disableExit}\r\n";
        }
        else
        {
            LogOutput += $"[{DateTime.Now:HH:mm:ss}] [WARN] DisableOutOfProcBuild.exe not found at {disableExe}. Set EnableOutOfProcBuild=0 in registry (STEP 3).\r\n";
        }

Then keep your existing devenv Process build + copy *.msi to outputFolder
(see docs/fixes/web-to-client-bridge-msi-full-fix.txt STEP 6).
