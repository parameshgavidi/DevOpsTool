PREREQ

SYMPTOM
-------
- UI LogOutput still shows: [INFO] Email notification sent to ...
- No email arrives
- Visual Studio → View → Output → Debug shows BOTH of:

  GenerateSystemLogFileEntry: An error occurred while Sending Emails
  System.ArgumentException: Keyword not supported: 'huixt2azeur...'
    at System.Data.SqlClient...
    at Microsoft.ApplicationBlocks.Data.SqlHelper.ExecuteDataset
    at GSS.GSSEmail.EmailCredentialList(...) in GSSEmail.cs:~336
    at GSS.GSSEmail.SendEmailByNetV2(...)

  GenerateSystemLogFileEntry: Missing SECUREMAILCREDENTIAL data in Process Settings


CAUSE (read the garbled "keyword")
----------------------------------
'huixt2azeur...' is NOT a SQL keyword. It is the START of an ENCRYPTED blob
that BuildTab passed as sGSSConnectionString.

Flow today:

  BuildTab.razor
    connectionString = LoadAppSettings() / appsettings   ← still ENCRYPTED
    SendEmailByNetV2(..., connectionString, true)
      → EmailCredentialList(sGSSConnectionString, true)
         → SqlHelper.ExecuteDataset(ENCRYPTED_BLOB, ...)
            → SqlClient parses first token as a keyword → ArgumentException
      → catch logs "An error occurred while Sending Emails..."
      → credentials never load
      → else branch logs "Missing SECUREMAILCREDENTIAL data..."
      → returns WITHOUT throw
  BuildTab logs success anyway

So "Missing SECUREMAILCREDENTIAL" here is usually a FOLLOW-ON message after
the DB call failed — not proof the row is absent (check again AFTER decrypt).


--------------------------------------------------------------------------------
FIX A (required) — decrypt GSS connection string BEFORE SendEmailByNetV2
--------------------------------------------------------------------------------

In BuildTab.razor ONLY — decrypt with the SAME Encryption.Crypto API
GSSEmail.cs already uses for Host/Port/UserId/Pwd (READ that file; do not edit it).

1. Open GSSEmail.cs (read-only) and find the decrypt call, e.g.:

     Encryption.Crypto objCrypto = new Encryption.Crypto();
     string host = objCrypto.DecryptString(CredentialList["Host"].ToString());
     //  ↑ use DecryptString (NOT Decrypt — Decrypt does not exist on Encryption.Crypto)

2. In BuildTab.razor, REPLACE the email send block with
   (adjust property names to match yours):

  try
  {
      var settings = LoadAppSettings();
      var fromEmail = settings.FromEmail ?? "GSSHelp@usps.gov";
      var recipients = settings.EmailRecipients; // your actual property
      var toEmails = (recipients != null && recipients.Count > 0)
          ? string.Join(";", recipients)
          : "devi.s.lam@usps.gov";

      // --- FIX: appsettings / LoadAppSettings often stores ENCRYPTED CS ---
      var encryptedCs = settings.ConnectionString
          ?? settings.GssConnectionString
          ?? throw new InvalidOperationException("GSS connection string missing in appsettings.");

      var crypto = new Encryption.Crypto();
      var connectionString = crypto.DecryptString(encryptedCs);   // NOT Decrypt
      // IntelliSense: DecryptFile / DecryptStream / DecryptString

      // Guard: plaintext must look like a SQL connection string
      if (string.IsNullOrWhiteSpace(connectionString)
          || connectionString.IndexOf('=') < 0
          || connectionString.StartsWith("huixt", StringComparison.OrdinalIgnoreCase)
          || connectionString.IndexOf("Data Source", StringComparison.OrdinalIgnoreCase) < 0
             && connectionString.IndexOf("Server", StringComparison.OrdinalIgnoreCase) < 0)
      {
          throw new InvalidOperationException(
              "GSS connection string did not decrypt to a SQL connection string. " +
              "Check Encryption.dll key and appsettings value.");
      }

      var mailSubject = $"DevOps Tool — files copied successfully";
      var mailBody = $"<html><body>...</body></html>"; // keep your existing body

      GSS.GSSEmail.SendEmailByNetV2(
          fromEmail, toEmails, mailSubject, mailBody, connectionString, true);

      LogOutput += $"[{DateTime.Now:HH:mm:ss}] [INFO] Email notification sent to {toEmails}\r\n";
  }
  catch (Exception emailEx)
  {
      LogOutput += $"[{DateTime.Now:HH:mm:ss}] [WARN] Email notification failed: {emailEx.Message}\r\n";
  }

3. If Encrypted value is ALREADY decrypted elsewhere in the app (e.g. a shared
   helper used for other DB calls), call THAT helper instead of inventing a
   second decrypt path:

     var connectionString = GetPlainGssConnectionString(); // existing helper

4. Rebuild → F5 → check Output → Debug:
   - ArgumentException "Keyword not supported: 'huixt..." MUST be GONE
   - If mail still fails, read the NEXT GenerateSystemLogFileEntry line


--------------------------------------------------------------------------------
FIX B — if after decrypt you STILL see Missing SECUREMAILCREDENTIAL
--------------------------------------------------------------------------------
Then EmailCredentialList connected, but Process Settings has no usable row.

Check in the GSS database pointed to by the decrypted connection string:

  - Table / process-settings store used by EmailCredentialList
    (often Process_Settings / similar — confirm in EmailCredentialList SQL)
  - Key / code: SECUREMAILCREDENTIAL
  - Values: Host, Port, UserId, Pwd, FromEmailId (encrypted as GSSEmail expects)

Until that row exists and decrypts, SendEmailByNetV2 hits the else branch:

  ExceptionHandling.GenerateSystemLogFileEntry(
      "System", "Email Component",
      "Missing SECUREMAILCREDENTIAL data in Process Settings",
      "SendEmailByPowerShell", sGSSConnectionString);

That is DATA / ops config — not a MAUI csproj fix.


--------------------------------------------------------------------------------
WORKAROUND — false "[INFO] Email sent" without changing GSSEmail.cs
--------------------------------------------------------------------------------
SendEmailByNetV2 swallows exceptions (you cannot change that). So:

1. In BuildTab, ONLY log success after decrypt guard passes AND the call
   returns — and ALSO tell the user to check Output → Debug for
   GenerateSystemLogFileEntry lines (real failures still land there).

2. Prefer logging a cautious message:

  GSS.GSSEmail.SendEmailByNetV2(
      fromEmail, toEmails, mailSubject, mailBody, connectionString, true);
  LogOutput += $"[{DateTime.Now:HH:mm:ss}] [INFO] Email send requested for {toEmails} (check Output→Debug if mail missing)\r\n";

3. Your BuildTab catch WILL fire for decrypt/guard failures (those are yours).
   It will NOT fire for SMTP / missing-credential failures inside GSSEmail.
