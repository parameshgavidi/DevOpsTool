OLD FLOW (do not use on Build anymore)
--------------------------------------
1. Build selected app (or Build All) → BuildApplication
2. BuildApplication calls GetLatestFromRepoAsync(app, ...)
3. For THAT app only:
   a) stash local changes under the project folder (keeps Install-Package etc.)
   b) fetch remote
   c) restore that project folder from upstream (get latest)
   d) stash pop (put local changes back on top of latest)
4. On success (true) → restore / clean PrecompiledWeb → msbuild / publish
5. On failure (false) → stop that app build (Status = Failed), log error

1) appsettings.json — CHANGE gitLatestCommand (keep local)
--------------------------------------------------------------------------------
YES — change the command. Remove git clean / bare git restore that WIPE local.

OLD (wipes local — do not use if you keep NuGet installs local):
  git fetch && git clean -fd -- "..." && git restore --source=@{u} ...

NEW (keep local + get latest for that project folder):
  1. git stash push -m "devops-pre-build" -- "<projectDir>"
  2. git fetch
  3. git restore --source=@{u} --staged --worktree -- "<projectDir>"
  4. git stash pop

Notes:
- cwd = Code Repo Root (build:repoRoot).
- Local Install-Package / packages.config edits are stashed, then re-applied after latest.
- No push to remote required for those local package fixes.
- Do NOT use git clean -fd here — that deletes local untracked files.
- If stash pop conflicts, OUTPUT LOG will show it; resolve in that project folder, then rebuild.
- If there is nothing to stash, "git stash push" still exits 0 (Git 2.13+ creates no stash / or use
  tolerating empty stash — if your Git errors on empty stash, prepend:
  git stash push -m "devops-pre-build" -- "<path>" || ver > nul
  on Windows cmd empty-stash can still succeed with "No local changes to save").
- @{u} must be set on the branch.
